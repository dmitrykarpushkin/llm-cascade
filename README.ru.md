# llm-cascade

[![CI](https://github.com/dmitrykarpushkin/llm-cascade/actions/workflows/ci.yml/badge.svg)](https://github.com/dmitrykarpushkin/llm-cascade/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

**Короткая сводка из шумной ленты втрое дешевле, чем если отдавать всё самой сильной модели.**

Для тех, кто сводит поток, где большая часть сообщений не важна: новостные каналы, тикеты поддержки, алерты,
отзывы. Дешёвый классификатор выкидывает очевидный мусор, маленькая модель оценивает остальное большими пачками,
а большая модель пишет итоговый текст только по лучшим кандидатам.

```text
$ cascade-digest examples/posts.jsonl --usage
{"classifier_in": 13, "classifier_kept": 10, ..., "filter_calls": 1, "items": 14, "unique": 13, "candidates": 10, "kept": 9}
Top
- Bitcoin ETF inflows hit a record $1.2 billion in a single day as BTC tests $118k — Market Wire https://example.com/mw/101
- Exchange hack: an invented exchange, Nimbus, halts withdrawals after a $40M hot wallet exploit — Chain Daily https://example.com/cd/56
- ...
```

*Офлайн-демо на выдуманной ленте из 15 постов: пустой пост и репост отсеяны до любой модели, спам и розыгрыш
не доходят даже до маленькой модели.*

## Зачем

- **В 3,4 раза дешевле, чем всё через Opus, при том же качестве сводки.** На одном дне реальной ленты (300 постов)
  каскад стоил $0,32 против $1,11 и сохранил столько же важных новостей (9 из 14 против 8 из 14).
- **Сбой делает прогон дороже, но не хуже.** Если классификатор лежит или не уверен, сообщение не выбрасывается,
  а идёт дальше к модели.
- **Не падает на кривом ответе модели.** JSON разбирается терпимо: битые элементы пропускаются, прогон идёт дальше.
- **Каждый прогон сам считает свою цену.** Сколько вошло и вышло на каждом этапе, сколько вызовов модели,
  сколько символов отправлено, сколько стоил классификатор.
- **Работает без ключей.** Для каждого этапа есть заглушка на ключевых словах, поэтому демо и все 28 тестов
  идут офлайн.

## Чем отличается

Замер на одних и тех же 300 постах 5 октября 2026 года; эталон — большая модель, которая оценила каждый пост
([подробности](docs/evaluation.md)):

| | Всё через маленькую модель (Haiku) | Всё через большую (Opus) | **llm-cascade** |
|---|---|---|---|
| Важных новостей в сводке | 6 из 14 | 8 из 14 | **9 из 14** |
| Цена одной сводки | $0,29 | $1,11 | **$0,32** |
| Время | 253 с | 137 с | 163 с |

Если нужен самый точный фильтр, а цена не важна, берите всё через большую модель (F1 фильтра 0,74 против 0,59).
Если запросы независимые — отдельные вопросы пользователей, — лучше подойдёт общий маршрутизатор вроде RouteLLM
или шлюз с фолбэками. Этот репозиторий — про пакетный случай, когда много сообщений борются за несколько мест
в одном тексте.

## Быстрый старт

```bash
git clone https://github.com/dmitrykarpushkin/llm-cascade && cd llm-cascade
pip install -e .
cascade-digest examples/posts.jsonl --usage        # офлайн-демо, без ключей и сети
```

С настоящими моделями: скопируйте `.env.example` в `.env`, загрузите его и добавьте `--live`. Этапы 1 и 2 вызывают
CLI `claude` с его собственным входом; этап 0 без ключа классификатора пропускается. Вместо CLI подойдёт любой
объект с методом `complete(prompt, model) -> str`: клиент SDK или локальная модель.

## Как устроено

```text
лента (JSONL) -> убрать пустые, склеить репосты
              -> этап 0: API-классификатор выкидывает уверенный мусор   (около цента за тысячу решений)
              -> этап 1: маленькая модель ставит оценки 1-5 пачками по ~60 тыс. символов
              -> этап 2: большая модель пишет сводку из сообщений с оценкой 3+
```

Этапы, решения в дизайне, API библиотеки и CLI `cascade-decide` описаны в [docs/design.md](docs/design.md)
(на английском).

## Статус и ограничения

Вынесено из ежедневной сводки, которая читает сотни постов в день из публичных новостных каналов; здесь —
переиспользуемое ядро с офлайн-заглушками и тестами. Цифры выше — это один день, по одному прогону на писателя
и эталон от модели, а не от людей: это направление, а не бенчмарк. Слабое место — фильтр на маленькой модели:
два одинаковых прогона совпали только на 42% отобранных постов ([исследование стабильности](docs/evaluation.md)).
